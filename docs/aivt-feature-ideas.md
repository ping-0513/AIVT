# AIVT Feature Ideas

Status: idea draft (2026-07-04).

あった方が良い機能の候補集。優先度タグ:

- `[MVP]` — 最初の診断フローと一緒に作るべきもの(CLAUDE.md の MVP 順序に対応)
- `[v1.x]` — MVP が動いたあとの早期追加
- `[将来]` — 図鑑・コミュニティ・研究段階

---

## 1. 診断コア(テスト体験)

- `[MVP]` **2つの受験モード**
  - 転記モード: 人間がモデルの回答を代理入力する(API を持たないユーザーも、アプリ内のキャラも測れる)
  - API 直結モード: モデルに直接 20 問を投げる(`tools/pilot_runner.py` がプロトタイプ)
- `[MVP]` 選択肢シャッフル+内部 ID(`aivt-16-future.md` の設計)
- `[MVP]` 途中保存・部分提出・未回答明示(同上)
- `[v1.x]` **反復モード**: 同じテストを N 回連続実行して確信度を出す(API モードなら全自動)。
  「AI はランダム」への反証はここで完成する
- `[v1.x]` **条件差分モード**: 同一モデルを「ペルソナ有/無」「システムプロンプト差し替え」
  「記憶有/無」「日付違い」で受けさせて、軸ごとの変化を差分表示
  (例:「ペルソナを載せたら S→M に変わった」)。AIVT にしかできない測定の本命

## 2. 結果・エンタメ

- `[MVP]` **シェアカード**: タイプ名+4軸バー(0-5)+強度(ゆらぎ/はっきり/くっきり)+確信度、
  モデル名と測定日入り。測定日が入ることで「あの頃の 4o」が記録になる
- `[v1.x]` **2体比較ビュー**: 軸ごとの一致/対立を並べる。同じ会社のモデル同士が対角に落ちたら
  ハイライト(4o vs 5 系の WFSE/GVMR 対角はここの看板になる)
- `[v1.x]` **兄弟年表**: 同一シリーズのタイプ変遷を時系列で(5 → 5.1 → … → 5.5)。
  「同じ会社・同じ系列でも全員違う」の可視化
- `[v1.x]` タイプ別の紹介文・強み・「この子への頼み方のコツ」
  (モデル選びの参考、という当初目標への直結コンテンツ)
- `[将来]` **人間モード+相性診断**: 同じ 20 問を人間が「AI にこう返してほしい」視点で受け、
  自分のタイプとモデルのタイプの相性文を出す。エンタメの最大化と実用(自分に合うモデル選び)の合流点

## 3. 図鑑・蓄積

- `[v1.x]` **モデル図鑑**: 1 モデル = 1 ページ。タイプ履歴、軸スコアの推移、
  美的指紋、名場面ログ(「o3 は銀貨だけ受け取った」「Claude は何回やっても指紋」)。
  プロジェクトの最終形はテストではなく図鑑、という位置づけ
- `[v1.x]` **ミニモジュール: どれが好き?**: 美的指紋の記録(古さ/新しさ/唯一性/物理…)。
  選択式・反復可・シャッフル可で、ほぼそのまま実装できる
- `[将来]` **自由回答プローブ**: 好きな食べ物、好きな色、名前を付けるなら——
  ブレ前提で「揺れ方」ごと記録する(Grok のタコス枠)
- `[将来]` **プローブ台本集**: 人魚・少年と剣・研究者の相談などの定型プロンプト+観察タグの
  チェックシート。台本を固定することで、定性実験を蓄積可能・比較可能にする
- `[将来]` 観察タグの別トラック記録: 能力系(比喩理解、前提保持)とノイズ系(セーフティ口調化)を
  価値観と混ぜずに保存

## 4. 研究・データ

- `[MVP]` **実行メタデータの完全記録**: モデル ID、測定日時、温度、システムプロンプトの有無、
  表示順。これがないと再現も経時比較もできないので、最初から
- `[v1.x]` 順番バイアスレポート: 表示位置×選択率の集計(シャッフルデータの副産物)
- `[v1.x]` パイロットダッシュボード: 軸ごとの「割れ具合」「モデル内一貫性」。
  割れない軸を予備軸と入れ替える判断材料
- `[将来]` 経時トラッキング: 同モデルを定期再測定し、タイプが変わったら記録
  (サイレントアップデート検出器としても面白い)
- `[将来]` データセットエクスポート: 匿名・オプトインの回答データを CSV/JSON で公開。
  「同じ質問をみんなで蓄積する」試みの研究的価値はここで回収する

## 5. 信頼・配慮

- `[MVP]` 「これは性格ではなく、観察された応答傾向です」の常設注記(擬人化の断定を避ける)
- `[MVP]` 結果保存はオプトイン(CLAUDE.md の既存方針)
- `[MVP]` モデルの格付けにしない: 全 16 タイプを肯定的に書く。負けタイプ・正解タイプを作らない

---

## 実装順の提案

CLAUDE.md の MVP 順(診断フロー → 保存 → 結果表示 → シェアカード → エクスポート → …)に沿いつつ、
Ver2 特有の追加として:

1. 診断フロー(転記モード、20 問、シャッフル、途中保存)
2. 結果表示(タイプ+4軸バー+強度)とシェアカード
3. 実行メタデータ記録と JSON エクスポート
4. API 直結モード(pilot_runner の Web 版)と反復モード
5. 2体比較ビュー
6. 条件差分モード
7. 図鑑ページとミニモジュール
